我把 GitHub 当作一张公开工作台：这里放真实项目、可复用的 Skill，以及把一个想法做成可运行产品的方法。

### 我在做的事

**[Spark Skills](https://github.com/China-Wesley/spark-skills) · 把方法变成可运行的 Skill**

把产品研究、设计与创作流程整理成 Codex 可以直接执行、验证和复用的工作流。不是只给一份提示词，而是把判断标准、产出物和验收方式一起交给 Agent。

**AI 产品实验 · 从真实需求到可验证的 App**

持续寻找适合个人开发者的窄需求，完成需求调研、产品定义、交互设计、开发与验证。我关心的不是「AI 能不能十分钟写完」，而是它最终能不能真的解决问题、稳定运行。

**内容创作 · 给普通人讲明白 AI，也讲工程师如何把事情做成**

目前主要写三类内容：AI 产品工程、职场实战、独立开发与副业实验。社会变化也会聊，但最终都会回到同一个问题：普通人怎样增加能力、收入和选择。

**工程实践 · 让 AI 接受真实世界的反馈**

我在研究怎样用上下文、工具调用、自动化测试和可回滚流程，让 Coding Agent 不只会生成代码，也能对结果负责。

---

### 我相信的几件事

**会生成，不等于会验证。** AI 可以很快给出一个看起来正确的答案，但「什么叫正确」仍然需要人先定义清楚。

**真实任务比 Demo 更诚实。** 一个工具有没有价值，要看它能不能在真实约束里完成任务，而不是只看演示时有多惊艳。

**把复杂问题讲明白，也是工程能力。** 好的解释不是减少细节，而是帮助别人看见真正影响结果的机制。

**做出来，才能形成自己的判断。** 我更愿意分享亲自做过的项目、踩过的坑，以及证据改变了我什么看法。
